# 胡柚、香柚病虫害识别阶段性研究思路汇报

## 汇报简版

前期实验发现，纯净背景柑橘叶片分类准确率已经达到95%～96%，继续在这类数据上换网络、刷精度意义不大；但模型换到其他品种和采集条件后会明显掉点，还会把缺素黄化误判成黄龙病。公司后续App虽然以近距离拍摄为主，但画面中可能同时包含多片叶、果实、枝条和复杂背景，所以我目前准备把问题改成：**复杂果园背景下胡柚、香柚病虫害对象的定位、识别和跨场景泛化。**

现有190张试拍中，184张是单叶、少叶或单果近景，只有6张多叶或场景图，因此目前还不能直接认定目标检测一定优于分类。计划先用200～300张先导数据，同时比较“整图分类＋弱定位”和“患病器官/病斑检测”：如果App能够稳定引导单器官近景，优先采用分类与局部病征建模；如果多器官、遮挡和位置提示需求明显，则采用检测。数据预计约1000张，先根据果园实际发生情况锁定3～5个高频病虫害类别，并另设健康/无明显异常类。黄龙病没有PCR，不作为本地确诊类别。公开橙、橘、柚数据用于预训练，胡柚、香柚数据负责微调和独立测试。

方法上不会预设一定采用YOLO。分类路线比较ConvNeXt、DINOv2特征微调及弱定位；检测路线比较YOLO、Faster R-CNN和RT-DETR。当前最有依据的改进是**多源柑橘迁移和背景鲁棒学习**：保留不同来源域，约束同一器官在不同背景下保持相同判断，减少模型学习设备和果园背景。若先导实验确认检测成立，再研究**病虫害分类与定位解耦**，使定位分支关注叶果轮廓，分类分支关注内部病斑、潜道和虫害特征。主动学习、双视图、病斑分割和手机端蒸馏作为后续扩展，不在第一阶段全部叠加。

下一步先完成目标果园病虫害发生情况调查和标签规范，再拿200～300张经复核的图片做任务形态与多模型先导实验，根据真实错误决定最终骨架和核心创新。当前需要进一步确认：App能否稳定引导单器官近景、实际是否需要输出位置，以及严重度分割是否属于必要功能。

## 一、目前发现的问题

前期主要围绕柑橘叶片分类和田间检测进行了调研与实验。现在可以确定，继续在纯净背景数据上提高分类准确率，研究价值已经比较有限。

本地实验中，EfficientNet-B0、ResNet50和MobileNetV3-Large在Mendeley五类柑橘叶片数据上的准确率都达到约95%～96%，说明干净背景、单叶分类已经接近饱和。但是，当模型直接迁移到另一套橙叶数据CitrusUAT时，不同模型的准确率出现明显差异，部分模型下降到22%～49%。此外，模型会把大量缺铁、缺镁和缺氮造成的黄化误判为黄龙病症状。

这说明真正需要解决的问题不是“在理想数据上继续提高一点准确率”，而是：

1. 果园背景复杂，图中可能同时出现多片叶、枝条和果实，模型需要先找到真正异常的对象。
2. 公开数据多为橙、橘或其他柑橘品种，与胡柚、香柚之间存在品种和采集条件差异。
3. 不同病虫害之间可能外观相似，同一种病虫害在不同光照、时期和设备下也会发生变化。
4. 公司App后续采集的数据可能存在类别不平衡、重复拍摄、标注不准确和未知病虫害。
5. 实际系统不能对所有图片都强制给出病名，需要允许“不确定或需要专家复核”。

因此，我准备把研究重点从纯净背景分类转向：

> **复杂果园背景下，胡柚、香柚病虫害对象的定位、识别和跨场景泛化。**

## 二、准备做什么任务

公司App预计以近距离拍摄为主，但采集人员不一定能保证画面中只有一片叶或一个果实。因此，暂不直接锁定检测，先保留两条任务路线：

- 单器官近景占主导且App可以稳定引导拍摄时，采用整图分类，并用类别激活图或局部病征分支提供弱定位；
- 一图多器官、遮挡和复杂背景较多，或业务明确要求指出异常位置时，采用患病器官或病斑检测；
- 低置信度、画质不合格或训练中未见过的情况统一输出“不确定/需要复核”。

现有190张试拍中，单叶/少叶近景165张、单果近景19张、多叶/场景图6张。该批数据只能说明当前拍摄习惯，不能代表未来App正式采集分布。第一阶段不要求所有图片标注病斑掩膜；黄化、煤污、卷叶和潜叶蛾潜道的边界标准不同，只有在严重度需求明确且边界可以稳定复核时，才对代表性子集增加掩膜。

如果后续公司明确需要病害严重度，可以再选择100～200张代表性图片，用SAM生成候选掩膜并人工修正，增加病斑分割和受害面积估计。

## 三、数据准备思路

### 1. 类别不宜一次设置太多

根据胡柚相关标准、农业部门资料和现有自采图，候选类别包括溃疡病、黄斑病、黑点病、炭疽病、潜叶蛾、黑刺粉虱或煤污症状、蚧类及螨类等。

但1000张图片不足以支撑十几个类别。计划先通过目标果园调查和第一批数据统计，锁定3～5个高频、视觉可辨、能够由专家确认的病虫害类别，并另设健康/无明显异常类。初步优先考虑：

1. 健康或无明显异常；
2. 溃疡病；
3. 潜叶蛾为害；
4. 黑刺粉虱/煤污复合症状；
5. 炭疽病或局部坏死斑；
6. 黑点病、树脂病、黄斑病中目标果园实际高发的一类。

黄龙病目前没有PCR，不作为确诊类别。可以暂时标为“疑似斑驳黄化”或“不确定”，由专家复核。

类别标签不采用“症状直接等于病名”的单层结构。每张样本分别记录器官、可见症状、疑似病虫害和证据等级：可见症状允许多选，疑似病名允许缺失，证据等级区分机器预标、农民判断、专家确认和PCR/实验确证。训练时只对已有的可靠标签计算相应损失，不把缺失病名补成推测值。

### 2. 公开柑橘数据的使用方式

公开橙、橘、柚数据可以用于训练，但不能直接与胡柚数据混在一起随机划分。计划保留每张图片的数据来源，采用：

```text
公开柑橘数据预训练
→ 胡柚、香柚数据有监督微调
→ 跨果园、跨日期、跨拍摄者独立测试
```

实验中比较：

- ImageNet初始化；
- 公开柑橘数据预训练；
- 公开数据与本地数据直接混合；
- 公开数据预训练后再进行目标品种微调。

这样可以回答“其他柑橘数据到底能否帮助胡柚、香柚”，而不是主观认为柑橘品种之间差异不大。

### 3. 建议App记录的简单信息

App第一版不需要复杂标注，但建议记录：

- 样本编号 `sample_id`；
- 品种：胡柚/香柚；
- 部位：叶片/果实/枝条；
- 农民判断的疑似类别，也允许选择“不确定”；
- 匿名果园编号、树号和采集人员编号；
- 拍摄日期、设备型号；
- 专家复核状态。

建议部分对象同时拍摄近景和稍远图。近景用于保留病斑细节；稍远图用于保留多叶、遮挡和真实背景，测试模型能否找到目标。没有必要所有对象都双拍，可以先让20%～30%的样本采用双视图，并使用同一个 `sample_id`。

## 四、基础方法准备怎么选

不会一开始就认定必须使用某一种任务或网络。准备先在同一套数据和同一分组划分下比较：

1. ConvNeXt-Tiny或DINOv2-S：单器官近景分类与弱定位基线；
2. YOLOv8n或YOLO11n：实时一阶段检测基线；
3. Faster R-CNN ResNet50-FPN：两阶段高精度检测基线；
4. RT-DETR-R18或R50：实时Transformer检测基线；
5. Mask R-CNN或SegFormer：仅在掩膜子集上评估病斑分割与严重度。

首先用200～300张经复核的图片做先导实验。分类路线报告Macro-F1、每类召回和弱定位质量；检测路线报告mAP50-95、每类召回和背景误检；两条路线共同比较跨拍摄者性能、推理速度和标注成本。最终任务和骨架由实验决定，而不是因为某种模型热门或论文数量多就提前决定。

### 各类基础模型在本研究中的作用

| 方法 | 主要作用 | 重点观察 |
|---|---|---|
| ConvNeXt/DINOv2分类＋弱定位 | 单器官近景基线 | 是否用更低标注成本达到可靠识别，定位解释是否可信 |
| YOLOv8n/YOLO11n | 实时检测和移动端基线 | 速度快，但是否容易受背景和类别不平衡影响 |
| Faster R-CNN | 小数据、高精度和RoI细分类基线 | 是否更适合区分相似病斑，跨拍摄者是否更稳定 |
| RT-DETR | 实时Transformer检测基线 | 全局上下文是否有助于遮挡、多叶和复杂背景 |
| Mask R-CNN/SegFormer | 病斑分割与严重度候选 | 掩膜成本是否换来稳定、可解释的严重度结果 |

模型筛选不会只看mAP最高值。如果某个模型整体指标略低，但跨果园、跨设备和稀有类别召回更加稳定，也可能更适合后续研究和实际部署。

### 拟研究方法的整体结构

```text
输入果园图像
   ↓
画质与拍摄形态判断
   ├─ 单器官近景 → 分类＋局部病征建模
   └─ 多器官/需定位 → 检测器定位 → 病征分类
   ↓
多源迁移与背景一致性训练
   ↓
类别、可选位置、置信度及“不确定”提示
```

共享骨干可以先采用ResNet50-FPN、RT-DETR轻量骨干或ConvNeXt-Tiny。若DINOv2局部特征在先导实验中确实带来增益，再将它作为冻结或部分微调的病征特征提取器，避免一开始使用过重模型。

### 分阶段训练方式

1. **通用初始化**：从ImageNet或官方检测预训练权重开始。
2. **公开柑橘预训练**：学习柑橘器官和通用病征，同时保留数据来源字段。
3. **目标品种微调**：在胡柚、香柚复核数据上训练所选任务头和具体类别。
4. **可靠性与部署**：使用跨果园验证集校准阈值；确定App端或服务器端后再蒸馏或量化。

如果公开数据只有整图类别而没有检测框，可以先训练分类分支或构建裁框预训练，不强行把不可靠伪框当作真实检测标注。

## 五、自己打算改进的地方

### 候选创新一：病虫害分类与器官定位解耦

普通目标检测模型通常让分类和位置回归共享特征，但本任务中两者关注的信息不同：

- 框出叶片或果实，需要关注轮廓、边缘和整体形状；
- 判断病虫害，需要关注器官内部的病斑、潜道、霉层、虫体和局部颜色变化。

准备借鉴检测领域的分类—定位解耦思想：

- 在共享多尺度特征之后建立两个独立的RoI或query分支；
- 定位分支重点学习叶片、果实边界，并使用IoU/L1等位置损失；
- 分类分支先抑制框内背景，再重点学习局部病征；
- 将器官整体特征与若干高响应局部patch进行融合；
- 使用DINOv2局部patch、类别激活区域或SAM器官掩膜辅助选择局部区域；
- 两个分支分别优化，只在输出阶段组合类别和位置。

如果最终采用YOLO，可以在检测头中进一步分离分类和回归特征；如果采用Faster R-CNN，可以直接在RoIAlign之后建立独立分支；如果采用RT-DETR，则可以让分类query与位置query使用不同的特征投影和监督。因此，这个创新点不依赖某一种检测器名称。

基本损失可以写成：

```text
总损失 = 目标存在损失
       + 位置回归损失
       + 病虫害分类损失
       + 局部病征约束
```

“局部病征约束”先从一种简单方案开始，例如同类病征特征靠近、不同类特征分离的监督对比损失。后续再比较局部一致性或类别原型约束，不能第一版同时加入多种损失，否则难以判断增益来源。

这一改进针对的是“器官边缘”和“内部病征”关注区域不一致的问题，比简单增加注意力模块更有明确依据。但它只有在先导实验确认检测主线成立，并观察到分类与定位冲突后，才作为核心创新。

### 当前优先创新：多源柑橘迁移与背景鲁棒学习

公开柑橘数据与公司App数据存在品种、设备、果园背景和拍摄方式差异。计划：

- 保留不同数据集的来源域标记；
- 公开柑橘数据负责预训练，本地数据负责目标微调；
- 使用人工bbox提示SAM，离线获得叶片/果实前景候选；
- SAM掩膜只用于辅助前景提取和数据增强，不作为人工真值；
- 将器官前景放到不同真实果园背景中，形成背景反事实样本；
- 约束同一个器官在原背景和替换背景下保持相同类别和相近特征；
- 必要时引入域泛化、原型匹配或教师—学生方法。

对应训练目标可以表示为：

```text
总损失 = 原始图任务损失
       + 换背景图任务损失
       + 前景特征一致性损失
       + 可选的跨来源类别原型损失
```

背景替换只作为训练增强，最终测试必须全部使用真实果园图片。实验设置“仅去背景”“仅背景替换”“背景替换+一致性”三个对照，证明增益不是简单增加数据量造成的。

这一部分希望解决“模型识别的是病虫害，还是拍摄设备、地面和背景”的问题。

### 候选创新二：多轴标签与部分标签学习

公司数据可能由农民初标、专家复核。农民可能能判断“这是虫害”或“这片叶有病”，但不一定能准确区分炭疽病、黑点病或其他相似叶斑。如果只接受专家级细标签，会浪费大量数据；如果直接相信农民细标签，又会引入噪声。

由于视觉症状与病名并不是稳定的一一对应关系，标签不强行组成单一树，而是分成四个可以独立缺失的轴：

```text
器官轴：叶片 / 果实 / 枝条 / 虫体
症状轴：黄化 / 坏死 / 潜道 / 煤污 / 木栓化 / ……（允许多选）
诊断轴：溃疡病 / 潜叶蛾 / 炭疽病 / ……（允许缺失）
证据轴：机器预标 / 农民判断 / 专家确认 / PCR或实验确证
```

训练时：

- 所有有效样本都可以监督器官轴；
- 农民或机器可以先标可见症状，但不能把症状直接写成病原学确诊；
- 只有经过可靠确认的样本才参与具体病虫害诊断损失；
- 缺少诊断标签的样本不计算该项损失，而不是填入猜测类别；
- 症状、诊断和证据等级矛盾时，将样本加入专家复核队列。

这种方法可以统一利用不同可靠程度的标签，也能降低专家标注压力。它是否作为正式创新，需要看公司实际标签质量；如果农民初标已经足够准确，则不增加该模块。

### 可选扩展：面向App的数据闭环

如果公司后续持续采集数据，可以采用主动学习：

```text
先标一部分
→ 训练初始模型
→ 自动选择最困难、最不确定、最有多样性的图片
→ 农民或专家复核
→ 继续训练
```

这样可以减少大量健康图、重复连拍和简单样本占用专家时间。该部分可以先作为数据生产流程，如果实验显示明显降低了标注成本，再考虑是否作为论文贡献。

每轮可以综合三个因素选样：

- 分类不确定：模型无法稳定判断类别；
- 定位不确定：不同增强或不同模型给出的框差异较大；
- 样本多样性：避免连续选择大量相似背景和同一症状连拍。

建议先人工标注200张，再每轮选择100～150张，直到新增一轮数据带来的提升明显减小。

### 可选创新：近景—稍远双视图

如果App能够保证同一对象拍摄近景和稍远图，可以训练：

- 近景教师使用完整器官和高清病斑学习细类别；
- 稍远学生在复杂背景中学习定位和分类；
- 利用 `sample_id` 将同一对象的两个视图对应起来；
- 对类别概率、器官特征或局部病征特征施加一致性约束；
- 训练完成后，推理阶段仍允许只上传一张图片，不强制用户双拍。

这一方向与App结合紧密，创新潜力较高，但依赖采集流程。计划先用100～150组配对样本验证，再决定是否升为主线。

### 不确定样本如何处理

第一阶段不直接实现完整的开放世界检测框架，而采用较稳妥的分级拒识：

1. 根据分类概率、特征到类别原型的距离和不同增强下的预测稳定性计算可信度；
2. 高可信样本输出具体病虫害；
3. 中等可信样本只输出粗类别，例如“疑似虫害”；
4. 低可信样本输出“无法判断，请补拍或人工复核”。

独立测试集应加入机械伤、缺素、强反光、模糊和未收录病虫害，评估模型能否拒绝错误输入，而不只是评估已知类别准确率。

## 六、实验如何证明方法有效

实验不能只报告最终准确率，准备包括：

### 1. 基线比较

先比较整图分类＋弱定位与患病器官/病斑检测的任务效用；检测成立后，再比较YOLO、Faster R-CNN和RT-DETR等不同范式。

### 2. 消融实验

- 共享检测头 vs 分类—定位解耦；
- 只使用全局器官特征 vs 加入局部病征特征；
- 普通单层类别标签 vs 器官—症状—诊断—证据多轴监督；
- 检测器自带分类头 vs DINOv2局部病征分类分支；
- ImageNet预训练 vs 公开柑橘预训练；
- 无背景处理 vs 背景重组和一致性约束；
- 随机选择标注样本 vs 主动学习选样；
- 有无近景—稍远双视图监督。

### 3. 泛化实验

- 跨胡柚/香柚品种；
- 跨果园或地块；
- 跨拍摄人员和设备；
- 跨日期或季节；
- 公开柑橘训练后直接测试目标域，以及少量目标数据微调后的变化。

### 4. 可靠性实验

- 低置信度拒识；
- 未知病虫害、机械伤、缺素和强反光等干扰样本；
- 每类召回率和误诊类型；
- 置信度是否与实际正确率一致。

检测指标以mAP50-95、每类AP和召回率为主；类别不平衡时补充Macro-F1；部署阶段再报告模型参数量、单张延迟和内存占用。拒识部分报告已知类准确率、未知样本召回和不同阈值下的准确率—覆盖率变化。

数据划分必须按 `sample_id`、树号、果园或拍摄者分组，不能把同一片叶的连续照片随机拆入训练集和测试集。

## 七、当前研究主线与决策条件

当前先锁定研究问题，不提前锁死任务形态：

> **复杂果园背景下胡柚、香柚病虫害识别的跨来源泛化与可靠性研究。**

整体流程为：

```text
果园发生调查与多轴标签
        ↓
200～300张先导数据
        ↓
分类＋弱定位  vs  器官/病斑检测
        ↓
多源柑橘迁移与背景鲁棒学习
        ↓
输出类别、可选位置和置信度
        ↓
低置信度样本进入复核
```

创新优先级暂定为：

1. 针对公开柑橘到胡柚、香柚以及不同果园和设备的分布差异，设计多源迁移和背景鲁棒训练策略。
2. 若检测路线成立，针对器官定位与内部病征识别目标不同，设计分类—定位解耦结构。
3. 若农民初标与专家诊断存在明显层级和缺失差异，再引入多轴部分标签学习。

主动学习、双视图、病斑分割和模型蒸馏作为可选扩展，不在第一阶段全部加入，避免方法堆叠。

## 八、下一步工作

1. 请公司或专家提供目标果园近两年的实际高发病虫害清单。
2. 与公司确定App需要记录的最小字段，以及是否支持部分双视图和目标点击。
3. 第一阶段采集并复核200～300张，按唯一对象统计，锁定3～5个高频病虫害类别，并另设健康/无明显异常类。
4. 比较分类＋弱定位与检测的任务效用、标注成本和跨场景表现。
5. 根据真实错误确定背景鲁棒、分类—定位解耦或多轴标签中哪一个作为核心方法。
6. 数据扩大到约1000张后，补充多随机种子、跨果园和跨设备实验。

## 九、当前需要确认的问题

1. App能否通过拍摄引导稳定获得单器官近景，还是必须处理较多多器官场景？
2. 主线更适合强调分类—定位解耦，还是强调跨品种、跨果园泛化？
3. 公司和专家是否能确定3～5个稳定病虫害类别，并完整复核测试集？
