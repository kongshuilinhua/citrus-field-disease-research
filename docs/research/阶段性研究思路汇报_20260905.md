# 胡柚、香柚病虫害识别阶段性研究思路汇报

> 本文是现阶段向老师汇报用的思路整理，方向尚未完全锁定，后续将根据公司App采集的数据和先导实验结果进一步调整。

## 汇报简版

前期实验发现，纯净背景柑橘叶片分类准确率已经达到95%～96%，继续在这类数据上换网络、刷精度意义不大；但模型换到其他品种和采集条件后会明显掉点，还会把缺素黄化误判成黄龙病。公司后续App虽然以近距离拍摄为主，但画面中可能同时包含多片叶、果实、枝条和复杂背景，所以我目前准备把问题改成：**复杂果园背景下胡柚、香柚病虫害对象的定位、识别和跨场景泛化。**

任务上先采用较简单的“患病器官框”：框出受害叶片或果实并判断病虫害类别，不要求全部画病斑掩膜。数据预计约1000张，先根据果园实际发生情况锁定4～6个高频类别，并由农民初标、专家复核测试集和疑难样本。黄龙病没有PCR，暂不作为确诊类别。公开橙、橘、柚数据用于预训练，胡柚、香柚数据负责微调和独立测试。

方法上不会预设一定采用YOLO。我准备先公平比较YOLO、Faster R-CNN、Cascade R-CNN、FCOS/RetinaNet和RT-DETR。自己目前考虑的主要改进有两点：第一，**将病虫害分类与器官定位解耦**，定位分支关注叶/果轮廓，分类分支关注器官内部病斑、潜道和虫害特征；第二，**研究多源柑橘迁移和背景鲁棒学习**，保留不同数据来源，约束同一器官在不同背景下保持相同判断，减少模型学习设备和果园背景。App主动学习、近景—稍远双视图、病斑分割和手机端蒸馏作为后续扩展，不在第一阶段全部叠加。

下一步先拿200～300张专家复核图完成多模型先导实验，再根据真实错误决定最终骨架和核心创新。希望老师重点帮助确认：患病器官级检测是否合适、主线更应强调分类—定位解耦还是跨场景泛化、以及是否需要把严重度分割作为毕业论文必要内容。

## 一、目前发现的问题

前期主要围绕柑橘叶片分类和田间检测进行了调研与实验。现在可以确定，继续在纯净背景数据上提高分类准确率，研究价值已经比较有限。

本地实验中，EfficientNet-B0、ResNet50和MobileNetV3-Large在Mendeley五类柑橘叶片数据上的准确率都达到约95%～96%，说明干净背景、单叶分类已经接近饱和。但是，当模型直接迁移到另一套橙叶数据CitrusUAT时，不同模型的准确率出现明显差异，部分模型下降到22%～49%。此外，模型会把大量缺铁、缺镁和缺氮造成的黄化误判为黄龙病症状。

这说明真正需要解决的问题不是“在理想数据上继续提高一点准确率”，而是：

1. 果园背景复杂，图中可能同时出现多片叶、枝条和果实，模型需要先找到真正异常的对象。
2. 公开数据多为橙、橘或其他柑橘品种，与胡柚、香柚之间存在品种和采集条件差异。
3. 不同病虫害之间可能外观相似，同一种病虫害在不同光照、时期和设备下也会发生变化。
4. 公司App后续采集的数据可能存在类别不平衡、重复拍摄、标注不准确和未知病虫害。
5. 实际系统不能对所有图片都强制给出病名，需要允许“不确定或需要专家复核”。

因此，我准备把研究重点从纯净背景分类转向：

> **复杂果园背景下，胡柚、香柚病虫害对象的定位、识别和跨场景泛化。**

## 二、准备做什么任务

公司App预计以近距离拍摄为主，但采集人员不一定能保证画面中只有一片叶或一个果实。因此，现阶段更倾向于做“患病器官级检测”：

- 框出受到病害或虫害影响的整片叶或整个果实；
- 为每个受害器官预测病虫害类别；
- 健康或未发现已知病虫害的图片可以不标框，作为负样本；
- 低置信度或训练中未见过的情况输出“不确定/需要复核”。

第一阶段不准备要求所有图片都标注病斑掩膜。原因是不同症状的边界不统一，例如黄化、煤污、卷叶和潜叶蛾潜道很难采用相同的病斑标准。框整片受害叶或果实的成本更低，也更适合约1000张的数据规模。

如果后续公司明确需要病害严重度，可以再选择100～200张代表性图片，用SAM生成候选掩膜并人工修正，增加病斑分割和受害面积估计。

## 三、数据准备思路

### 1. 类别不宜一次设置太多

根据胡柚相关标准、农业部门资料和现有自采图，候选类别包括溃疡病、黄斑病、黑点病、炭疽病、潜叶蛾、黑刺粉虱或煤污症状、蚧类及螨类等。

但1000张图片不足以支撑十几个类别。计划先通过目标果园调查和第一批数据统计，锁定4～6个高频、视觉可辨、能够由专家确认的类别。初步优先考虑：

1. 健康或无明显异常；
2. 溃疡病；
3. 潜叶蛾为害；
4. 黑刺粉虱/煤污复合症状；
5. 炭疽病或局部坏死斑；
6. 黑点病、树脂病、黄斑病中目标果园实际高发的一类。

黄龙病目前没有PCR，不作为确诊类别。可以暂时标为“疑似斑驳黄化”或“不确定”，由专家复核。

### 2. 公开柑橘数据的使用方式

公开橙、橘、柚数据可以用于训练，但不能直接与胡柚数据混在一起随机划分。计划保留每张图片的数据来源，采用：

```text
公开柑橘数据预训练
→ 胡柚、香柚数据有监督微调
→ 跨果园、跨日期、跨拍摄者独立测试
```

实验中比较：

- ImageNet初始化；
- 公开柑橘数据预训练；
- 公开数据与本地数据直接混合；
- 公开数据预训练后再进行目标品种微调。

这样可以回答“其他柑橘数据到底能否帮助胡柚、香柚”，而不是主观认为柑橘品种之间差异不大。

### 3. 建议App记录的简单信息

App第一版不需要复杂标注，但建议记录：

- 样本编号 `sample_id`；
- 品种：胡柚/香柚；
- 部位：叶片/果实/枝条；
- 农民判断的疑似类别，也允许选择“不确定”；
- 匿名果园编号、树号和采集人员编号；
- 拍摄日期、设备型号；
- 专家复核状态。

建议部分对象同时拍摄近景和稍远图。近景用于保留病斑细节；稍远图用于保留多叶、遮挡和真实背景，测试模型能否找到目标。没有必要所有对象都双拍，可以先让20%～30%的样本采用双视图，并使用同一个 `sample_id`。

## 四、基础方法准备怎么选

不会一开始就认定必须使用某一种网络。准备先在同一套数据、同一划分和同一输入尺寸下比较：

1. YOLOv8n或YOLO11n：实时一阶段检测基线；
2. Faster R-CNN ResNet50-FPN：两阶段高精度基线；
3. Cascade R-CNN：逐级提高框质量；
4. FCOS或RetinaNet：非YOLO一阶段基线；
5. RT-DETR-R18或R50：实时Transformer检测基线；
6. DINOv2-S裁框分类：判断是否需要单独的细粒度分类分支。

首先用200～300张经专家复核的图片做先导实验，比较mAP50-95、每类召回率、跨拍摄者性能、推理速度和标注成本。最终主骨架由实验决定，而不是因为某种模型热门或论文数量多就提前决定。

### 各类基础模型在本研究中的作用

| 方法 | 主要作用 | 重点观察 |
|---|---|---|
| YOLOv8n/YOLO11n | 实时检测和移动端基线 | 速度快，但是否容易受背景和类别不平衡影响 |
| Faster R-CNN | 小数据、高精度和RoI细分类基线 | 是否更适合区分相似病斑，跨拍摄者是否更稳定 |
| Cascade R-CNN | 高质量定位基线 | 多阶段框优化能否减少叶片重叠时的错误框 |
| FCOS/RetinaNet | 非YOLO一阶段对照 | anchor-free或Focal Loss是否适合复杂背景与少量前景 |
| RT-DETR | 实时Transformer检测基线 | 全局上下文是否有助于遮挡、多叶和复杂背景 |
| DINOv2裁框分类 | 独立细粒度分类基线 | 单独分析框内病征是否明显优于检测器自带分类头 |

模型筛选不会只看mAP最高值。如果某个模型整体指标略低，但跨果园、跨设备和稀有类别召回更加稳定，也可能更适合后续研究和实际部署。

### 拟研究方法的整体结构

```text
输入果园图像
   ↓
共享骨干网络 + 多尺度特征
   ↓
候选器官定位（叶片/果实）
   ├─ 定位分支：轮廓、边缘、尺度 → bbox
   └─ 分类分支：器官内部病征 → 病虫害类别
          ├─ 全局器官特征
          ├─ 局部病斑/潜道/虫害特征
          └─ 粗类别与细类别分层预测
   ↓
类别、位置、置信度及“不确定”提示
```

共享骨干可以先采用ResNet50-FPN、RT-DETR轻量骨干或ConvNeXt-Tiny。若DINOv2局部特征在先导实验中确实带来增益，再将它作为冻结或部分微调的病征特征提取器，避免一开始使用过重模型。

### 分阶段训练方式

1. **通用初始化**：从ImageNet或官方检测预训练权重开始。
2. **公开柑橘预训练**：学习柑橘器官和通用病征，同时保留数据来源字段。
3. **目标品种微调**：在胡柚、香柚专家复核数据上训练器官框和细类别。
4. **可靠性与部署**：使用跨果园验证集校准阈值；确定App端或服务器端后再蒸馏或量化。

如果公开数据只有整图类别而没有检测框，可以先训练分类分支或构建裁框预训练，不强行把不可靠伪框当作真实检测标注。

## 五、自己打算改进的地方

### 创新点一：病虫害分类与器官定位解耦

普通目标检测模型通常让分类和位置回归共享特征，但本任务中两者关注的信息不同：

- 框出叶片或果实，需要关注轮廓、边缘和整体形状；
- 判断病虫害，需要关注器官内部的病斑、潜道、霉层、虫体和局部颜色变化。

准备借鉴检测领域的分类—定位解耦思想：

- 在共享多尺度特征之后建立两个独立的RoI或query分支；
- 定位分支重点学习叶片、果实边界，并使用IoU/L1等位置损失；
- 分类分支先抑制框内背景，再重点学习局部病征；
- 将器官整体特征与若干高响应局部patch进行融合；
- 使用DINOv2局部patch、类别激活区域或SAM器官掩膜辅助选择局部区域；
- 两个分支分别优化，只在输出阶段组合类别和位置。

如果最终采用YOLO，可以在检测头中进一步分离分类和回归特征；如果采用Faster R-CNN，可以直接在RoIAlign之后建立独立分支；如果采用RT-DETR，则可以让分类query与位置query使用不同的特征投影和监督。因此，这个创新点不依赖某一种检测器名称。

基本损失可以写成：

```text
总损失 = 目标存在损失
       + 位置回归损失
       + 病虫害分类损失
       + 局部病征约束
```

“局部病征约束”先从一种简单方案开始，例如同类病征特征靠近、不同类特征分离的监督对比损失。后续再比较局部一致性或类别原型约束，不能第一版同时加入多种损失，否则难以判断增益来源。

这一改进针对的是本任务中“器官边缘”和“内部病征”关注区域不一致的问题，比简单增加注意力模块更有明确依据。

### 创新点二：多源柑橘迁移与背景鲁棒学习

公开柑橘数据与公司App数据存在品种、设备、果园背景和拍摄方式差异。计划：

- 保留不同数据集的来源域标记；
- 公开柑橘数据负责预训练，本地数据负责目标微调；
- 使用人工bbox提示SAM，离线获得叶片/果实前景候选；
- SAM掩膜只用于辅助前景提取和数据增强，不作为人工真值；
- 将器官前景放到不同真实果园背景中，形成背景反事实样本；
- 约束同一个器官在原背景和替换背景下保持相同类别和相近特征；
- 必要时引入域泛化、原型匹配或教师—学生方法。

对应训练目标可以表示为：

```text
总损失 = 原始图检测损失
       + 换背景图检测损失
       + 前景特征一致性损失
       + 可选的跨来源类别原型损失
```

背景替换只作为训练增强，最终测试必须全部使用真实果园图片。实验设置“仅去背景”“仅背景替换”“背景替换+一致性”三个对照，证明增益不是简单增加数据量造成的。

这一部分希望解决“模型识别的是病虫害，还是拍摄设备、地面和背景”的问题。

### 创新点三：分层标签与部分标签学习

公司数据可能由农民初标、专家复核。农民可能能判断“这是虫害”或“这片叶有病”，但不一定能准确区分炭疽病、黑点病或其他相似叶斑。如果只接受专家级细标签，会浪费大量数据；如果直接相信农民细标签，又会引入噪声。

可以将标签分成三层：

```text
器官层：叶片 / 果实 / 枝条
粗类别层：健康 / 病害 / 虫害 / 不确定
细类别层：溃疡病 / 潜叶蛾 / 煤污复合症状 / ……
```

训练时：

- 所有样本都可以监督器官层；
- 农民能够确认病害或虫害时，监督粗类别层；
- 只有专家确认的样本才参与细类别损失；
- 缺少细标签的样本不计算细类别损失，而不是填入猜测类别；
- 粗类别和细类别预测矛盾时，将样本加入专家复核队列。

这种方法可以统一利用不同可靠程度的标签，也能降低专家标注压力。它是否作为正式创新，需要看公司实际标签质量；如果农民初标已经足够准确，则不增加该模块。

### 创新点四：面向App的数据闭环

如果公司后续持续采集数据，可以采用主动学习：

```text
先标一部分
→ 训练初始模型
→ 自动选择最困难、最不确定、最有多样性的图片
→ 农民或专家复核
→ 继续训练
```

这样可以减少大量健康图、重复连拍和简单样本占用专家时间。该部分可以先作为数据生产流程，如果实验显示明显降低了标注成本，再考虑是否作为论文贡献。

每轮可以综合三个因素选样：

- 分类不确定：模型无法稳定判断类别；
- 定位不确定：不同增强或不同模型给出的框差异较大；
- 样本多样性：避免连续选择大量相似背景和同一症状连拍。

建议先人工标注200张，再每轮选择100～150张，直到新增一轮数据带来的提升明显减小。

### 可选创新：近景—稍远双视图

如果App能够保证同一对象拍摄近景和稍远图，可以训练：

- 近景教师使用完整器官和高清病斑学习细类别；
- 稍远学生在复杂背景中学习定位和分类；
- 利用 `sample_id` 将同一对象的两个视图对应起来；
- 对类别概率、器官特征或局部病征特征施加一致性约束；
- 训练完成后，推理阶段仍允许只上传一张图片，不强制用户双拍。

这一方向与App结合紧密，创新潜力较高，但依赖采集流程。计划先用100～150组配对样本验证，再决定是否升为主线。

### 不确定样本如何处理

第一阶段不直接实现完整的开放世界检测框架，而采用较稳妥的分级拒识：

1. 根据分类概率、特征到类别原型的距离和不同增强下的预测稳定性计算可信度；
2. 高可信样本输出具体病虫害；
3. 中等可信样本只输出粗类别，例如“疑似虫害”；
4. 低可信样本输出“无法判断，请补拍或人工复核”。

独立测试集应加入机械伤、缺素、强反光、模糊和未收录病虫害，评估模型能否拒绝错误输入，而不只是评估已知类别准确率。

## 六、实验如何证明方法有效

实验不能只报告最终准确率，准备包括：

### 1. 基线比较

比较YOLO、Faster R-CNN、FCOS/RetinaNet、RT-DETR等不同范式。

### 2. 消融实验

- 共享检测头 vs 分类—定位解耦；
- 只使用全局器官特征 vs 加入局部病征特征；
- 普通单层类别标签 vs 器官—粗类别—细类别分层监督；
- 检测器自带分类头 vs DINOv2局部病征分类分支；
- ImageNet预训练 vs 公开柑橘预训练；
- 无背景处理 vs 背景重组和一致性约束；
- 随机选择标注样本 vs 主动学习选样；
- 有无近景—稍远双视图监督。

### 3. 泛化实验

- 跨胡柚/香柚品种；
- 跨果园或地块；
- 跨拍摄人员和设备；
- 跨日期或季节；
- 公开柑橘训练后直接测试目标域，以及少量目标数据微调后的变化。

### 4. 可靠性实验

- 低置信度拒识；
- 未知病虫害、机械伤、缺素和强反光等干扰样本；
- 每类召回率和误诊类型；
- 置信度是否与实际正确率一致。

检测指标以mAP50-95、每类AP和召回率为主；类别不平衡时补充Macro-F1；部署阶段再报告模型参数量、单张延迟和内存占用。拒识部分报告已知类准确率、未知样本召回和不同阈值下的准确率—覆盖率变化。

数据划分必须按 `sample_id`、树号、果园或拍摄者分组，不能把同一片叶的连续照片随机拆入训练集和测试集。

## 七、目前最倾向的研究主线

现阶段最倾向的题目是：

> **复杂果园背景下基于多源柑橘迁移与分类—定位解耦的胡柚、香柚病虫害检测方法。**

整体流程为：

```text
公开柑橘与公司App数据
        ↓
多源预训练与目标品种微调
        ↓
检测器定位受害叶片/果实
        ↓
定位分支学习器官边界
分类分支学习局部病征
        ↓
输出病虫害类别、位置和置信度
        ↓
低置信度样本进入专家复核
```

主创新暂定为两点：

1. 针对器官定位与内部病征识别目标不同，设计分类—定位解耦的病虫害检测结构。
2. 针对公开柑橘到胡柚、香柚以及不同果园/设备的分布差异，设计多源迁移和背景鲁棒训练策略。

主动学习、双视图、病斑分割和模型蒸馏作为可选扩展，不在第一阶段全部加入，避免方法堆叠。

## 八、下一步工作

1. 请公司或专家提供目标果园近两年的实际高发病虫害清单。
2. 与公司确定App需要记录的最小字段，以及是否支持部分双视图和目标点击。
3. 第一阶段采集并专家复核200～300张，锁定3～4个高频类别。
4. 完成六类基础模型的公平比较。
5. 根据真实错误确定分类—定位解耦、背景鲁棒或双视图中哪一个作为核心方法。
6. 数据扩大到约1000张后，补充多随机种子、跨果园和跨设备实验。

## 九、希望老师帮助确认的问题

1. 以“患病器官级检测”为第一阶段任务是否合适？
2. 主线更适合强调分类—定位解耦，还是强调跨品种、跨果园泛化？
3. 是否需要把严重度分割作为毕业论文的必要内容？
4. 公司和专家是否能确定4～6个稳定类别，并复核测试集？
5. 论文应更偏算法创新，还是允许“方法＋App数据闭环＋真实场景验证”的应用型路线？
