# 柑橘病害数据集可用性复核（2026-11-22）

> 复核对象：上一轮研究报告与仓库实际依赖的柑橘数据资产，以及报告引为“公开可用”的近邻工作数据。
> 判定口径只回答一件事：**这套数据现在能不能拿到、许可允不允许写进论文、本地是否完整、标注能不能支撑报告里的实验**。
> 本报告不改动任何原始数据，只新增审计脚本与中间结果（`数据集复核_20261122/`）。

> **入库说明（2026-11-22）**：本报告由协调者从工作区根目录归档到 `docs/data/`，脚本与中间 JSON 存于 `docs/data/scidb复核_20261122/`。
> **待核冲突**：本报告称 testB/testC 缺 S12 藻斑，但 `方法路线扩展_20261031/统一检测数据/data.yaml` 的第 13 号类别即 S12 且在 testB 有 43 个标签框，`191_创新方向与论文调研/36_S12专项的重要修正.md` 也直接在 testB/testC 上使用 S12。三处记录不一致，**在按原始 `label_object.json` 复核前，不得据本报告推断“S12 不存在”**。
> 其余结论（testA 同图、640×480、类别平衡、PCR 对齐、许可证）独立成立。

**四个会改变研究计划的结论：**

1. **SciDB 本地是完整的**：train 7192 + val 898 + testA/B/C 各 602 = 9896 张，与数据集元数据声明的规模一致；`tests.zip` 确含 testA/B/C 三个子包，`PCRs.zip` 含 `PCR+`（139 张）与 `PCR-`（463 张）。公开数据集清单里“14 类”的说法与 `data.yaml` 的 15 类不一致。
2. **testB/C 不能再当独立测试集，这一点被数据本身坐实了**：不仅因为被反复使用，还因为 **testB 的 602 张里有 598 张能与 PCR 结果一一对齐**（像素级 NCC 中位数 = 1.0），也就是 testB 同时带着“症状类别标签”和“病原学结果”两套标签。这是资产，也是污染证据。
3. **报告 P3 里“真值难获得、要 4–12 小时专家”的成本估算可以直接删掉一半**：HLB 的病原学真值已经在仓库里，且能与 testB 一键对齐（`数据集复核_20261122/pcr_testB映射.json`）。真正缺的不是 HLB 真值，而是**其他病害的病原学真值**和**独立新域**。
4. **“独立配对域偏移测试集”在公开数据里确实没有替代品**：本次核验的 12 个柑橘公开集中，唯一具备“同批材料、多成像条件”结构的是 SciDB 的 testB/testC（同叶、田间 vs 白底），但它已被开发使用；自采 190 张里只有 18 对几何可配准、3 对确认同叶。所以报告 P2 的“必须新采”成立，但可以先拿 18 对做先导。

## 二、复核方法

- **一手页面**：DataCite API（DOI 元数据/许可）、Zenodo Records API（文件、校验值、许可）、Mendeley Data Public API（文件清单、SHA256、许可）、Crossref（期刊论文）、HuggingFace Datasets API、GitHub API、数据集官方页。
- **本地逐文件清点**：对 `scidb_det`、`统一检测数据`、`数据集_整理`、`datasets/`、`D:\病虫害论文\自采数据` 全部计数、核对标签配对。
- **自建质检**（脚本已归档，可重跑）：
  - MD5 跨划分精确重复；
  - dHash（9×8）近重复 + NCC≥0.999 复核，区分“真同图”与“白底哈希假阳性”；
  - 亮度/饱和度抽样，验证 testC 白底；
  - 逐类标签 id 合法性、每划分缺失类别；
  - PCR 包与 testB 的一对一匹配（dHash 候选 + NCC 复核）。
- **判定分级**：A＝许可清晰且本地可用可直接进论文；B＝可用但受分辨率/许可/标签粒度限制；C＝来源或许可不明，不可作为论文证据；D＝私有，只能报受限指标。

**质检发现（四条硬伤，都必须写进论文的数据说明）**

1. **类别数口径不一致**：`data.yaml` 定义 **15 类**（S0 others + 2 健康 + 12 病害），但 `公开数据集清单.md` 写“14 类（12 病害 + 2 健康）”。实际每个划分只出现 **14 类**：
   - train/val/testA 缺 `S0 others`；
   - **testB/testC 缺 id 14 = `S12 Algal spot and moss`（藻斑）**。
   → 仓库里“救回 S12 藻斑”“S12 系统性缺陷”这类结论**不能在 testB/testC 上成立**，只能在源 val 或 testA 上讲，引用前必须核对编号映射。
2. **testA 有 9 张与训练集是同一张图**（仅重编码，NCC ≥ 0.999，MSE = 0）：如 `testA_t0_29.jpg` ↔ `Btrain_3-HLB-1-185.jpg`（见 [同图样例](testA与训练集同图样例.png)）。另有 3 组 train↔val 为 MD5 完全相同的文件。testB、testC 复核后为 **0 张**（testC 的 78 个 dHash 候选全部是白底导致的假阳性）。
   → testA 的 92.36% mAP50 有约 1.5% 的乐观偏差，量级不大但必须披露，或剔除这 9 张复算一次。
3. **testC 的白底成立，但三套都是 640×480**：抽样亮度/饱和度 testA 120.3/0.367、testB 117.7/0.367、**testC 161.2/0.203**，与“B 中同对象取下置白背景板”一致（见 [三条件样例](三条件样例.png)）。但全部图像被压到 640×480，**小病斑的细粒度定位实验会先被分辨率卡住**，这一点不能归因于模型。
4. **类别完全平衡（每类 43 张）**：testB 的 602 张 = 14 类 × 43。这意味着 testB 上算出来的 per-class 指标是平衡口径，**不能直接外推田间先验分布**。

**新增发现：PCR 结果可以与 testB 精确对齐**

`PCRs.zip` 里是 `PCR+`（139 张）与 `PCR-`（463 张），共 602 张，文件名形如 `1-3- (23).jpg`。用 dHash + NCC 对齐后：

- **599 对匹配、覆盖 598 张不同的 testB 图像**；NCC 最小值 0.99982、中位数 **1.0** → 不是“相似”，是同一批图；剩余 4 张未能对齐（多为文件名不带标号、疑似重复拍摄）。
- 只有 1 处一对多冲突，核查后是**同一张图同时出现在 `PCR+` 和 `PCR-` 里**（NCC = 1.0、平均绝对差 = 0），即**至少 1 例正负标签自相矛盾**（`t3_1_1.jpg`）。

重建出的交叉表（作者未随数据提供该映射表，这是本报告重建）：

| 症状类别 | PCR+ | PCR− |
|---|---:|---:|
| S2 健康叶 | 39 | 3 |
| S3 斑驳黄化 | 39 | 3 |
| S4 红鼻果 | 22 | 20 |
| S5 缺锌 | 13 | 30 |
| S6 明脉 | 12 | 31 |
| S8 缺镁 | 2 | 40 |
| S11 脂斑 | 10 | 33 |
| S7 均匀黄化 / S9 缺硼 / S10 炭疽 / S14 溃疡 / S0 其他 / S1 健康果 / S13 煤污 | 0 | 各 43 |

→ **这张表本身就是 P3 最需要的证据**：它把“症状级标签”和“病原学标签”放在同一批样本上，可以直接量化“症状 ≠ 病原”的规模。但有两个必须写清的限定：(a) 映射是本报告用图像内容重建的，不是官方发布；(b) `PCR−` 只代表 CLas 阴性，**不等于健康**，不能反推“缺素/炭疽”。

**判定：A（可用）**，但 testA 有 1.5% 同图、testB/C 无 S12、全库 640×480、testB 类别平衡这四条必须在论文数据节写明。

### 3.12 报告引为“公开”的两个近邻：OWPDD 与 POSR

- **OWPDD**：仓库 [JiuqingDong/OWPDD](https://github.com/JiuqingDong/OWPDD) 存在（755 KB、2 star、**无 LICENSE**），内容全是 detectron2 代码 + `COCO.xlsx` + 配置，**没有任何图像数据**。
  → 报告说“已公开实现”没错，但**“公开数据”不成立**；想在柑橘上复现它的 known/unknown 协议，得自备检测数据。
- **POSR（Meng et al. 2023, CEA 215:108408）**：DOI 有效，Elsevier 订阅制，**未检索到公开数据集 DOI**，数据可用性未能一手核实。
  → 只能引方法，不能引数据；做对照只能自己在 SciDB 上实现 leave-one-class-out。

**这两条直接抬高报告 P8（通用开放世界检测）的成本，也说明“跟 OWPDD 比数据”是不现实的。**

## 四、对报告三条主线的影响
