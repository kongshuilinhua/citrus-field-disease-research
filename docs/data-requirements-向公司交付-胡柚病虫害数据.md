# 胡柚 / 香柚病虫害图像数据需求单

> 用途：本研究团队与公司共建"复杂果园背景下胡柚、香柚病虫害识别"研究体系，需向公司提出图像数据采集与标注要求，用于模型训练、跨场景评测与后续 App 产品积累。请公司按本需求单组织数据，研究团队提供采集工具、标注模板、专家复核与确诊协助。
> 两条采集路径：**A 基地定向采集**（公司组织人员到果园按标准流程采集，可现场初判）与 **B App 随手拍众包**（公司员工或农户经 App 采集，弱标签、覆盖广、自然分布）。两条路径可同时进行，共用同一套字段与标签体系。

---

## 一、数据总量与类别构成

起步目标合计约 **1000–1500 张可用图像**，两条路径合计。按"独立叶片/果实"计约 **500–700 个对象**，因每对象通常拍**近景 + 挂枝自然景两版**，张数 ≈ 对象数 × 2。

### 类别构成（按优先级）

| 优先级 | 类别 | 目标对象数 | 说明 |
|---|---|---|---|
| **必采（锚定）** | 健康 / 无明显异常 | 150 | 7 月高发、症状清晰、公开集也有，最稳落点 |
| **必采（锚定）** | 溃疡病 | 150 | 同上 |
| **重点采** | 缺素黄化（尽量分缺镁 / 缺锌 / 缺氮…） | 100 | 最容易与黄龙病混淆，是本研究关键区分类 |
| **尽量采** | 炭疽病 | 60 | 7 月可能偏少，采不到不硬凑 |
| **尽量采** | 其它（疮痂 / 黑点 / 煤烟病 / 潜叶蛾等虫害） | 50–80 | 记录的实际发生情况为准 |
| **重点采** | 黄龙病疑似 | 10–20（**送 PCR**） | **不做现场判断**，只标记 + 记位置 + 采样送检 |
| 果实 | 健康果 / 溃疡果 / 红鼻果（仅疑似） | 每类几十个 | 7 月多幼果，先采现有症状，秋季果期再扩 |

### 分布原则

1. **锚定类占大头**——健康 + 溃疡各 150，先把这两类采实，保证全流程先跑通。
2. **缺素要采够**（≥100）——这是治"缺素↔黄龙病混淆"的关键类。
3. **稀有类尽力就好**——长尾属正常现象，后续可用增广 / 少样本方法补。
4. **香柚、胡柚尽量各半**——课题核心是跨品种，两品种都需有代表性。
5. **每类留约 20% 作为测试集**，且这部分尽量来自**未进入训练的树 / 地块**，否则评测结果虚高。
6. **同叶 / 同果不要密集连拍**——同一对象拍 1–2 张即可，连续照片会导致评测泄漏。

## 二、路径 A：基地定向采集 SOP

### 每片病叶拍"两版"（关键）

- **① 贴近单叶**：叶片占满画面、对焦病斑、看清细节 → 用于对齐公开单叶数据集、做分类。
- **② 自然挂枝**：退后拍带枝条 / 背景的自然状态（复杂果园背景）→ 与 ① 的差异，即本课题要研究的"实验室 → 田间"域差。
- 单叶为主；随手的多叶合影也保留（供以后抠叶 / 检测用）。

### 刻意多样化

- 多光照：晴天 / 阴天、上午 / 中午、顺光 / 逆光。
- 叶**正反面都拍**（溃疡初期、脂点等在背面更明显）。
- 换不同树、地块、树龄；覆盖 **10–15 棵不同树 + 多角度**。
- 避免集中在同一背景（同一堵墙 / 同一块布前拍等于白采）。

### 确诊与初判安排

- **现场请老师 / 农技员 / 植保站人员**参与初步判断（尤其溃疡 vs 疮痂、炭疽、缺素 vs 早期黄龙病），这是数据能否使用的关键。
- **黄龙病只标记疑似，不现场判定，采样送 PCR 确诊**；确诊后才可作为标签。
- 拿不准的病例一律记"待确认"，不硬归。

---

## 三、路径 B：App 随手拍众包 SOP

### 拍摄引导（App 内提示）

- 画面主体尽量为 1 片叶或 1 个果实；若画面含多叶 / 枝条 / 果实，**保持真实自然状态**（这正是研究复杂背景所需）。
- 先拍一张**近景特写**（对焦病斑），再退一步拍一张**挂枝自然景**（保留背景），两版归入同一 `sample_id`。
- 遇到明显病叶 / 病果就拍，不刻意挑选；也可顺手拍健康叶作对照。
- 提示拍摄者：**换一棵树、换个方位、换个时间再拍**，避免连续对着同一对象连拍。

### App 记录字段（路径 B 必填）

同上文第四节字段表，由 App 自动记录 `sample_id`、拍摄时间、设备型号、定位、拍摄者编号，并让拍摄者选择"疑似类别"（允许选"不确定"）。

### 众包的数据特点与应对

- 众包图片**标签弱、不确定多、批次无控**，研究团队会将农民/机器的判断记为"证据等级 = 农民判断 / 机器预标"，仅用于缩小专家复核范围，**不直接作为训练标签**。
- 众包图片天然覆盖多种设备、光照、果园背景、拍摄习惯——**这正是本课题最需要的多样性**，其价值在于"真实分布"，不在于"标签准确"。
- 众包可能出现同一对象被不同拍摄者重复采集、同一片叶连拍多张，研究团队会做**去重审计**（见第六节）。

## 四、两类路径共用的字段表

无论 App 记录还是表格记录，每张 / 每个对象以下字段必填：

| 字段 | 必填 | 说明 |
|---|---|---|
| `sample_id` | ✅ | 唯一样本编号（每片叶 / 果一个） |
| 品种 | ✅ | 胡柚 / 香柚 |
| 部位 | ✅ | 叶片 / 果实 / 枝条 |
| 拍摄日期时间 | ✅ | YYYY-MM-DD HH:MM |
| 天气 | 建议 | 晴天 / 阴天 / 雨后 |
| 树号 | ✅ | 匿名化即可，需能区分同一棵树 |
| 地块号 | ✅ | 匿名化即可 |
| 拍摄设备 | 建议 | 手机型号，用于分析设备域差 |
| 拍摄者编号 | ✅ | 匿名化即可（路径 B 由 App 记录） |
| 定位（仅路径 B） | 建议 | 可选，用于分析地块分布 |
| 叶正 / 反 | 建议 | 正面 / 背面（溃疡初期背面更明显） |
| 农民 / 现场判断类别 | 待确认 | 允许选"不确定"；**是待确认类别，不是确诊** |
| 专家复核状态 | 待复核 | 研究团队负责 |
| `paired_id` | 条件 | 同一对象近景 + 稍远两版共用一个 ID，用于双视图研究 |

### 标签采用"多轴"结构（不强行症状 = 病名）

| 标签轴 | 内容 | 是否允许缺失 |
|---|---|---|
| 器官 / 对象 | 叶、果、枝、虫体 | 否 |
| 可见症状属性 | 黄化、斑驳、坏死、潜道、煤污、木栓化…（**可多选**） | 是 |
| 疑似病虫害诊断 | 溃疡病、潜叶蛾、炭疽病… | 是 |
| 证据与确认等级 | 机器预标 / 农民判断 / 专家确认 / PCR、实验确证 | 否 |

训练时研究团队**只对已有标签计算损失，不把缺失的病名补成推测值**。该体系允许不同可靠程度（农民初标、专家复核、PCR 确证）的样本统一使用，同时保留"确有证据确诊"与"仅视觉疑似"的严格区别。

---

## 五、确诊规则（硬性要求）

1. **黄龙病（HLB）不做现场判断**。肉眼不可靠，只标记"疑似 + 记录位置 + 采样送 PCR"。PCR 阳性才可作为"黄龙病"标签；无 PCR 的疑似样本只能作为"疑似黄化 / 不确定"，**绝不作为"黄龙病确诊"**。
2. **缺素 vs 早期黄龙病外观极像**。难以区分的黄叶一律标"待确认"，不硬归为缺素或黄龙病。
3. 溃疡 / 炭疽 / 缺素等类别，现场或本人判断只能作为**初判**，**最终标签由研究团队专家复核**确认。
4. 农民 / 机器的初标仅用于缩小复核范围，**不作为训练标签真值**。

## 六、数据去重与防泄漏

1. **同源去重**：同一叶片 / 果实的连续照片、同一对象被不同人反复采集，须归入同一组，评测时不得拆分到不同数据划分。
2. **按对象分组划分**：随机划分会高估性能，研究团队将按 `sample_id`、树号、地块或拍摄者分组，不随机拆分。
3. **批次与类别绑定的风险（重点关注）**：若采集高度集中在"今天专拍溃疡、明天专拍缺素"，则**采集批次与病害类别高度相关**，模型可能学到"批次 / 设备 / 光照"而非"病征"。研究团队会用诊断探针检测并打散，但**建议公司在采集时有意交叉批次**。此条对数据质量影响最大，请优先配合。

---

## 七、数据交付要求

请公司配合提供：

1. **原始图像**（不压缩、不裁剪、尽量保留 EXIF）。
   - *注意：完整原始图像与 EXIF 只保存在研究环境，不上传 GitHub 协作仓库；仓库仅存索引、清单与汇总。*
2. **对应字段表**（CSV 格式，见第四节），与图像按 `sample_id` 一一对应。
3. **设备 EXIF**（或设备型号字段），用于分析设备域差与采集偏差。
4. **文件名规则**：建议 `sample_id.jpg`，便于精确对应与去重审计。

## 八、需公司确认 / 承诺的前提

| 事项 | 公司需确认 | 对研究的影响 |
|---|---|---|
| **黄龙病 PCR 检测** | 公司能否（或联系机构）将疑似样本送 PCR？ | 决定黄龙病类别处理方式。若无法做 PCR，黄龙病只能作为"疑似黄化"，**建议至少有疑似样本送检** |
| **现场初判人员** | 能否协调农技员 / 植保站参与（路径 A）？ | 决定溃疡 / 炭疽 / 缺素初判可靠度；最终仍由研究团队专家复核 |
| **字段承诺** | 能否保证 `sample_id`、树号、地块号、拍摄者 ID 等字段不缺失？ | 决定跨域评测轴与分组划分能否成立，**是研究能否做跨果园 / 跨设备评测的前提** |
| **双视图** | 能否对部分对象拍近景 + 稍远两版（`paired_id`）？ | 支撑双视图研究；若成本高，可缩减到 20–30% 样本 |
| **批次打散** | 能否在采集时交叉批次，避免"批次 ↔ 类别"强绑定？ | 决定"背景 / 设备 / 批次"是否污染病征信号；**影响最大** |
| **数据敏感性** | 能否接受"原始图 + EXIF 仅存本地，git 只存汇总"？ | 遵循项目隐私与轻量仓库规则 |

## 九、研究团队将提供

- 采集 App（路径 B）或表格模板（路径 A），含必填字段与拍摄引导；
