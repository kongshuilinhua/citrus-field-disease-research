# 胡柚、香柚病虫害图像数据采集规范

## 一、数据范围

- 采集对象：胡柚、香柚的叶片和果实。
- 采集内容：病害、虫害及健康对照图像。
- 图像类型：普通手机或相机拍摄的RGB彩色照片。
- 数据规模：现有图片与新采图片均可使用。先整理或采集200～300张进行检查，确认类别和拍摄方式后扩充至约1000张可用图像。
- 类别数量：根据果园近两年的实际发生情况，选择3～5种常见、能够可靠确认的病虫害，另设健康/无明显异常类。

缺素、机械损伤、日灼等情况不作为主要识别类别，但可保留少量图像，用于测试模型是否会误判。黄龙病在没有PCR等可靠检测依据时，不作为确诊类别；疑似图片只记录为“斑驳黄化/待确认”。

## 二、拍摄要求

1. 以近距离拍摄为主，确保叶片、果实或病虫害症状清晰可见。
2. 保留真实果园背景，不需要摘下后放到纯色背景前拍摄。
3. 同一片叶或同一个果实最多拍1～2张，避免大量连续重复照片。
4. 建议约20%～30%的对象同时拍摄两张：
   - 近景图：突出叶片、果实和症状细节；
   - 稍远图：保留枝条、多叶、遮挡和周围背景。
5. 尽量覆盖不同果园、树木、拍摄人员、手机、日期、天气和光照条件。
6. 症状可能出现在叶背时，补拍叶片反面。
7. 照片应使用原始分辨率，不加滤镜、水印、文字或人为标记，不提前裁剪病斑。
8. 严重模糊、过曝、主体被手遮挡或无法看清症状的照片需要重新拍摄。

画面中不要求始终只有一片叶。单叶近景和包含多叶、枝条或果实的自然场景都可以保留，以便后续比较分类和目标检测方案。

## 三、每张图片需要记录的信息

| 字段 | 要求 | 示例或说明 |
|---|---|---|
| `image_id` | 必填 | 每张图片的唯一编号 |
| `sample_id` | 必填 | 同一叶片或果实的不同照片使用同一编号 |
| 品种 | 必填 | 胡柚 / 香柚 |
| 部位 | 必填 | 叶片 / 果实 / 枝条 |
| 疑似类别 | 必填 | 可填写具体类别，也允许填写“不确定” |
| 果园或地块编号 | 必填 | 使用匿名编号，不需要填写具体地址 |
| 树号 | 建议 | 能够区分是否来自同一棵树即可 |
| 拍摄日期 | 必填 | 年-月-日 |
| 拍摄者编号 | 必填 | 使用匿名编号 |
| 拍摄设备 | 建议自动记录 | 手机或相机型号 |
| 拍摄视图 | 必填 | 近景 / 稍远场景 |
| 复核状态 | 必填 | 未复核 / 已复核 / 无法确认 |

拍摄人员只需要提供初步判断，不要求直接画检测框或病斑掩膜。拿不准时填写“不确定”，不要强行归类。

## 四、类别与复核要求

1. 正式采集前，先整理目标果园近两年常见病害和虫害清单，再确定最终类别。
2. 病虫害类别尽量由农技人员或相关专家确认。
3. 验证集、测试集以及外观容易混淆的样本需要重点复核。
4. 农民或普通采集人员提供的类别只作为初步判断，后续可以修正。
5. 黄化不能直接标为黄龙病；煤污、坏死、卷叶等可先记录可见症状，再确认具体原因。
6. 如果某一类别样本过少或无法可靠确认，不强行加入第一阶段训练。

## 五、数据交付形式

需要提供以下两部分：

1. 原始JPG图像：不压缩、不裁剪、不修改文件内容。
2. 一份CSV或Excel信息表：每行对应一张图片，至少包含第三节中的必填字段。

图片和信息表通过 `image_id` 对应。无需提前划分训练集、验证集和测试集，后续将按果园、树号、拍摄者和同一对象进行分组，避免重复照片进入不同集合。

已有历史图片如果缺少个别字段，可以先提供，并在信息表中标为“未知”；后续新采图片按本规范记录。

建议目录结构：

```text
dataset/
├─ images/
│  ├─ IMG000001.jpg
│  ├─ IMG000002.jpg
│  └─ ...
└─ metadata.xlsx
```

## 六、需要提前确认的事项

1. 现有是否已经积累胡柚或香柚病虫害照片，数量和类别大致如何？
2. 目标果园近两年最常见的病害和虫害有哪些？
3. 能否协调农技人员或专家对主要类别和关键样本进行复核？
4. 后续采集能否覆盖胡柚、香柚以及不同果园、树木和拍摄人员？
5. App能否记录 `sample_id`、品种、部位、果园编号、树号、拍摄者、疑似类别和拍摄视图？
6. 能否让部分对象同时拍摄近景和稍远场景图？
7. 预计可以提供的数据量和采集时间分别是多少？

以上事项确认后，再根据实际类别分布确定每类采集数量，不提前硬性规定某一种病虫害必须达到固定数量。
