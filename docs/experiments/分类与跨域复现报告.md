# 柑橘叶病分类 Baseline 复现报告

> 复现日期：2026-07-10　｜　脚本：`train_cls_baseline.py`　｜　结果：`results/`
> 一句话结论：**在公开 Mendeley 柑橘叶（实验室干净背景）上，三种主流骨干微调后准确率一致落在 95~96%、宏 F1 ~97%，且第 3 个 epoch 即收敛——实验室干净背景分类确已接近饱和、无改进空间。这为"把重心转向跨品种 + 实验室→田间"提供了自己动手跑出来的第一手依据。**
> **M0 补测（§9）**：把该干净模型直接搬到异域（orange 品种）上，准确率从 96% 崩到 **22~49%**（轻量骨干），且**缺素黄叶被大量误判成黄龙病**（MobileNetV3 上 Fe/Mg/N/Zn 达 89~100%）——域差距与"缺素 vs HLB 混淆 / 开放集"问题被一并实测坐实。

---

## 一、目的
用最标准的迁移学习流程，在公开柑橘叶数据集上复现一个分类 baseline，目的有三：
1. 坐实课题前提——"干净背景分类已饱和"不是听来的，是自己跑出来的；
2. 打通"数据→训练→评测→存档"的完整管线，后续跨品种/域适应实验直接复用；
3. 得到后续方法要对比的**同分布起跑线**（IID clean baseline）。

## 三、数据核实
- 来源：Mendeley Citrus `3f83gxmv57`（叶 609，CC BY 4.0），本地 `数据集_整理/源域_Mendeley叶5类`，已按 8:2 分好 train/val。
- 5 类：`black_spot（黑斑）/ canker（溃疡）/ greening（黄龙病）/ healthy（健康）/ melanose（黑点）`。

| 类别 | train | val |
|---|---|---|
| black_spot | 137 | 34 |
| canker | 131 | 32 |
| greening | 164 | 40 |
| healthy | 47 | 11 |
| **melanose** | **11** | **2** |
| 合计 | 490 | 119 |

> ⚠ **长尾**：melanose 仅 13 张（11+2），验证集只有 2 张——它的指标不具统计意义（见局限）。

## 四、方法
- 骨干：ImageNet 预训练，替换分类头为 5 类，全网微调。
- 增广（train）：RandomResizedCrop(224, 0.7~1.0) + 水平翻转 + ColorJitter；val：Resize→CenterCrop(224)。
- 优化：AdamW(lr=3e-4, wd=1e-4) + CosineAnnealing，CrossEntropy，batch=32，40 epoch，固定随机种子 42。
- 选型：按验证集**宏 F1** 取最优 epoch 出最终报告。

## 五、结果

### 三骨干总览（同一 train/val）
| 模型 | 参数量级 | 最优 epoch | Accuracy | 宏 F1 |
|---|---|---|---|---|
| EfficientNet-B0 | 轻量(~5M) | 3 | **95.80%** | **97.28%** |
| ResNet50 | 强参照(~25M) | 26 | **95.80%** | 97.25% |
| MobileNetV3-Large | 部署候选(~5M) | 31 | 94.96% | 96.74% |

> 三个架构差距 <1%，结论不依赖某一模型。EfficientNet-B0 **第 3 epoch** 就到顶，收敛极快 = 任务对干净数据而言过于容易。

### 各类 F1（以 EfficientNet-B0 为例）
| 类别 | Precision | Recall | F1 |
|---|---|---|---|
| black_spot | 0.914 | 0.941 | 0.928 |
| canker | 1.000 | 1.000 | 1.000 |
| greening | 0.949 | 0.925 | 0.937 |
| healthy | 1.000 | 1.000 | 1.000 |
| melanose | 1.000 | 1.000 | 1.000（n=2，不可信） |

### 混淆矩阵（三模型一致的错误）
```
          预测→ black_spot canker greening healthy melanose
black_spot         32       0       2        0       0
canker              0      32       0        0       0
greening            3       0      37        0       0
healthy             0       0       0       11       0
melanose            0       0       0        0       2
```
**唯一系统性错误 = black_spot ↔ greening 互混**（黑斑病斑点 与 黄龙病斑驳在纯 RGB 叶片上视觉相近）。canker / healthy 几乎零错。

## 六、关键发现
1. **饱和坐实**：三骨干均 ~96%、宏 F1 ~97%，EfficientNet-B0 第 3 epoch 收敛——干净背景分类没有精度改进空间，符合课题立论。
2. **错误集中在语义相近类**：black_spot↔greening 是唯一混淆点，说明剩余误差是"类间视觉歧义"，不是"模型不够强"——堆更大模型无用，需靠更多信息（多视角/文本知识/更细症状）而非换骨干。
3. **长尾已现形**：melanose 13 张，任何指标都不可信；真实自采/田间场景这种少样本类会更多，**类不均衡是必须处理的工程点**（重采样/类权重/少样本）。

## 七、局限（诚实说明）
- **同分布、干净背景**：本 baseline 是 IID clean，**没有**跨品种、也**没有**田间复杂背景，天花板高是必然。真实难点（掉点）尚未触及。
- **验证集小（119 张）**：±1~2 张就摆动约 1%，数值别过度解读；melanose(n=2) 的 100% 无意义。
- **未做从零训对照**：本次只做"ImageNet 预训练微调"，尚缺"从零训 vs 预训练"对照（下一步补）。

## 八、对课题的意义与下一步
本 baseline 证明了"干净背景已饱和"，**真正要量化的是把它放到跨品种 + 田间会掉多少（M0）**：

- **M0（已完成第一步，见 §9）**：已用 CitrusUAT（orange，含 HLB 确诊+缺素）测出跨品种掉点；**仍缺"复杂田间背景"这一重**——需真田间集（福建 SciDB 需登录）或自采胡柚补上。
- 之后：按方案 C1 叠域适应（CDAN+E / FBR 背景重组）把掉点补回来；或按 R3 换自监督预训练看数据效率。

> 已具备：可复用训练脚本、三个基线权重（`results/best_*.pt`）、完整评测管线。M0 只需接入田间测试集即可跑。

## 九、M0 跨域掉点实测（2026-07-10）

### 测试设置（诚实说明"域"的性质）
- 用上面训好的三个"干净 Mendeley"模型，**不做任何再训练**，直接在 **CitrusUAT** 上测。
- CitrusUAT（Zenodo 8294078，CC BY 4.0）：953 张 **orange（Citrus sinensis）** 单叶图，**深灰底受控拍摄**（经查样图，非复杂田间背景），HLB 经 **qPCR 确诊**。
- 与训练 5 类干净重叠的类：**Healthy→healthy、HLB→greening**，共 **143 张**（healthy 100 + HLB 43）。
- ⚠ 因此本 M0 量化的是 **"跨品种(mandarin→orange) + 跨采集设置"** 的域移，**不是**"实验室→田间复杂背景"那一重（CitrusUAT 背景仍干净）。后者需真田间集或自采胡柚，属后续。

### 结果一：重叠类掉点（对照干净基线）
| 模型 | 干净基线 | 跨域·严格5类 top1 | 跨域·2类(healthy/greening) |
|---|---|---|---|
| EfficientNet-B0 | 95.80% | **22.38%** | 48.25% |
| ResNet50 | 95.80% | **82.52%** | 95.80% |
| MobileNetV3-Large | 94.96% | **48.95%** | 73.43% |

> 判读：2 类若"永远猜 healthy"= 100/143 = **70%**。EfficientNet-B0 的 48% **低于这个下限**——它不是"不确定"，而是**偏向性地把健康 orange 叶判成病叶**（100 张健康里 48→greening、24→melanose），即"过度报病"。

### 结果二：缺素黄化被误判为黄龙病（直接验证"缺素 vs HLB 混淆"）
把 CitrusUAT 缺素类（训练时**从未见过**）喂进去，统计被判成 greening(HLB) 的比例：

| 缺素类 | EffNet-B0→HLB | ResNet50→HLB | MobileNetV3→HLB |
|---|---|---|---|
| Fe 缺铁 (n=100) | 58% | 58% | **92%** |
| Mg 缺镁 (n=100) | 51% | 13% | **89%** |
| Mn 缺锰 (n=30) | 0% | 23% | **90%** |
| N 缺氮 (n=50) | 62% | 54% | **100%** |
| Zn 缺锌 (n=100) | 6% | 4% | **95%** |

> **"缺素黄化 vs 黄龙病"混淆被实测坐实**：只学过 5 类、没见过缺素的模型，会把大量缺素黄叶硬判成黄龙病（MobileNetV3 上 Fe/Mg/N/Zn 高达 89~100%）。含义：①早期 HLB 与缺素的鉴别是真难点；②**开放集/未知类必须处理**——自采会遇到大量训练集没有的病/虫/缺素，否则一律被塞进最近的已知类而误报。

### 关键结论
1. **域差距真实且巨大**，且**轻量模型最不抗域移**（EffNet-B0 96%→22%、MobileNetV3 也崩；ResNet50 反而稳 82.5%/95.8%）——"落地要轻量"与"跨域要稳"存在矛盾，正是域适应 / 蒸馏要解决的核心。
2. **误判有系统方向**：健康→报病、缺素→HLB、病害间互串（HLB↔canker）——是域偏置，不是随机噪声。
3. **量化到手**：这组掉点 + 缺素混淆，就是方案 B/C1「M0 坐实掉点」的第一手论据，也为"为什么需要域适应 + 开放集"提供了实证。

### 本 M0 的局限
- CitrusUAT 背景仍干净，**未覆盖"复杂田间背景"**这一重；真正的 lab→field 需真田间集（福建 SciDB，登录墙）或自采胡柚。
- HLB 重叠仅 43 张，2 类样本偏小，数值看趋势即可。
- 未做置信度校准，"过度报病"含未校准成分；但同一管线下 ResNet50 稳、EffNet-B0 崩，说明主因是**模型泛化差异**，非管线 bug。
