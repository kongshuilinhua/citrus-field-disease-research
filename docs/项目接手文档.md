## 1. 接手后要完成什么

本项目研究常山胡柚等柑橘类作物的 RGB 图像病虫害识别。当前最重要的任务不是继续堆模型，而是重新回答四个问题：

1. 真实研究背景是什么：纯净背景分类、复杂田间识别，还是跨场景泛化？
2. 根据现有自采照片，应该做分类、目标检测、语义/实例分割，还是分类与分割多任务？
3. YOLO 应该是主方法、对照模型、部署模型，还是标注工具？
4. 怎样从其他作物的成熟方法中提炼可迁移思路，并形成有问题依据的创新，而不是简单拼接模块？

接手 Agent 应以“任务和数据决定方法”为原则。不要因为图片尚未标注就预设必须采用无监督学习，也不要因为 YOLO 论文多就机械排除 YOLO。

## 2. 用户与导师的最新要求

用户是计算机专业研究生，研究对象是胡柚/柑橘病虫害图像。

导师最新反馈：

- 纯净背景准确率已经很高，不适合继续作为主要创新空间。
- SciDB 上继续做 YOLO 是一种可能，但 YOLO 方向拥挤，单纯改模块未必有说服力。
- 不要把调研范围限制在柑橘，应查看水稻、玉米、小麦、番茄、苹果、葡萄、棉花等作物的方法。
- 除 YOLO 外，需要认真比较分类网络、Faster R-CNN、DETR 系、分割网络、视觉 Transformer、Mamba、基础模型和多任务方法。
- 最终方法应能迁移到胡柚真实场景，而不是只在公开数据集上得到高分。

用户希望 Agent 帮助完成自采图片的预识别和标注。这表示可以走正常的全监督路线；自动预标注只是降低人工成本，并不限定必须做无监督、自监督或半监督。

## 3. 已有实验结果：接手时必须知道的事实

### 3.1 干净背景分类基线

数据：Mendeley 柑橘叶五类验证集，共 119 张。

| 模型 | Accuracy | Macro-F1 |
|---|---:|---:|
| EfficientNet-B0 | 95.7983% | 97.2849% |
| ResNet50 | 95.7983% | 97.2484% |
| MobileNetV3-Large | 94.9580% | 96.7353% |

结论：同源干净背景分类已接近饱和。继续换分类骨干追求零点几的提升，研究价值有限。

限制：验证集同时承担模型选择和结果报告作用，没有严格独立测试集；melanose 验证样本仅 2 张。

### 3.2 跨数据集测试：Mendeley → CitrusUAT

模型只在 Mendeley 上训练，直接测试 CitrusUAT 中重叠的 Healthy 与 HLB 类，共 143 张。

| 模型 | 严格五类 Accuracy | 限定二类 Accuracy |
|---|---:|---:|
| EfficientNet-B0 | 22.3776% | 48.2517% |
| ResNet50 | 82.5175% | 95.8042% |
| MobileNetV3-Large | 48.9510% | 73.4266% |

结论：跨品种、跨采集条件后，模型表现高度依赖骨干；不能笼统地说“所有模型都崩”，但轻量模型存在明显域鲁棒性问题。

CitrusUAT 是深灰背景受控拍摄，不是真正复杂田间场景。因此该实验只能说明跨品种和跨采集设置差距，不能直接声称完成了 Lab-to-Field 田间验证。

### 3.3 缺素被误判成黄龙病

训练模型没有见过缺素类。MobileNetV3-Large 将 CitrusUAT 中多种缺素样本判为 greening/HLB 的比例为：

- 缺铁：92%
- 缺镁：89%
- 缺锰：90%
- 缺氮：100%
- 缺锌：95%

结论：闭集模型会把未知症状硬塞进已知病害。未来无论是否把开放集识别作为主创新，都应至少报告未知类拒识、置信度或人工复核机制。

### 3.4 其他已完成实验

| 实验 | 结果 | 关键限制 |
|---|---|---|
| ViT-B/16 四类分类 | Accuracy 97.9798%，Macro-F1 97.7273% | 每个 epoch 在名为 test 的集合上评测并选最优，存在测试集参与选模 |
| YOLOv8n-cls，CitrusUAT 12 类 | Top-1 99.4737%，Top-5 100% | 同数据集验证指标，无外部独立测试 |
| 无泄漏 SimCLR，ResNet18 | Accuracy 70.59%，Macro-F1 75.49% | 优于随机初始化 56.30%，但低于 ImageNet 初始化 87.39% |
| DANN 单次正式实验 | 严格五类 75.5245%，限定二类 79.7203% | 历史与正式运行波动较大，需要多随机种子和严格目标域划分 |
| SciDB YOLOv8n 检测基线 | mAP50 92.3633%，mAP50-95 85.2715% | 已很强，继续小改 YOLO 的提升空间和创新性有限 |
| 三通道低保真重建 | mAP50 80.2351%，mAP50-95 70.8319% | 从头训练、非官方忠实实现 |
| 三通道作者补充代码 | mAP50 91.3641%，mAP50-95 84.0533% | 低于本地 YOLOv8n 预训练基线 |
| Leaf-Only-SAM | 6/6 完成推理 | 部分黄化病叶有效覆盖率接近 0，绿色阈值后处理不可靠 |

正式队列的 7 项实验都已真实运行完成，并保留日志、权重、截图和 SHA-256 清单。真实性确认不代表实验协议全部适合直接写入论文。

### 5.2 图像形态

- 主要是田间原位的单叶、少叶或单果近距离特写，不是整株或树冠远景。
- 叶片/果实通常占画面较大，背景是真实枝叶、地面和自然光。

### 5.5 训练前强制要求

1. 由农技专家复核病名和健康标签。
2. 黄化样本不得直接标为黄龙病；可能是缺素、衰老、病害或光照影响。
3. 疑似连拍组必须整体进入同一个训练、验证或测试集合。
4. 最好按树号、地块、拍摄序列分组，而不是随机按图片划分。
5. 第一批需要裁剪水印，人工黑色记号应排除或设为忽略区。
6. 在标签确认前保留 raw 原图不变，不要直接按推测病名重命名文件。

## 6. 当前方法判断：不是最终结论，但应作为起点

### 6.1 YOLO 的合理定位

YOLO 仍然可以使用，尤其适合实时部署和病斑/虫体框标注。但建议将其定位为：

- 强检测基线；
- 自动预标注工具；
- 实时部署模型；
- 蒸馏后的学生模型。

不建议仅以“YOLO + 注意力 + 新 IoU + 小目标层”作为论文主要创新。SciDB 上 YOLOv8n 基线已经达到较高指标，普通模块改造很难说明实际问题价值。

### 6.2 值得系统比较的非 YOLO 路线

- 监督分类：ConvNeXt、Swin Transformer、DINOv2 特征微调。
- 两阶段检测：Faster R-CNN、Cascade R-CNN。
- Transformer 检测：Deformable DETR、RT-DETR、DINO。
- 语义/实例分割：DeepLabV3+、SegFormer、UPerNet、Mask R-CNN、Mask2Former。
- 多任务：分类 + 病斑分割 + 严重度估计。
- 背景鲁棒学习：叶片前景约束、背景替换一致性、域泛化。
- 相似症状区分：全局叶片特征 + 局部病斑特征、监督对比损失、原型中心约束。

### 6.3 当前更值得验证的研究问题

建议优先验证：

> 复杂田间背景下，能否利用跨作物病征表征和前景—背景解耦，提高胡柚少样本病虫害的定位、分类与严重度估计？

可选题目雏形：

> 《复杂田间背景下基于跨作物表征迁移与前景—背景解耦的胡柚病害识别方法》

这不是最终锁题。必须先根据标签能否确认、病斑是否适合分割以及新增数据规模再决定。

### 6.4 可能形成的创新点

1. 跨作物病征迁移：迁移斑点、坏死、黄化、霉层、卷曲等通用形态，而不是直接照搬其他作物病名。
2. 前景—背景解耦：使用原始图、叶片前景图和背景替换图的一致性约束，降低背景捷径。
3. 全局—局部融合：全叶分支分析黄化和叶脉模式，局部分支分析病斑纹理与边界。
4. 分类、分割和严重度联合：同时输出类别、病斑区域和受害面积比例。
5. 未知症状拒识：低置信度或远离已知原型的样本进入人工复核，而不是强制输出病名。

不要一次堆入全部五点。论文主方法最好只保留一到两个核心改进，其余作为数据流程、评测或扩展。

## 7. 建议新 Agent 继续调研的具体任务

### 7.1 文献范围

优先检索 2024—2026 年一手论文和官方代码，作物范围不要限制在柑橘：

- 水稻、玉米、小麦等微小病斑检测；
- 番茄、苹果、葡萄等 Lab-to-Field 分类；
- 棉花、花生等 Faster R-CNN 与 YOLO 对比；
- 多作物 PlantSeg/PlantWild 上的分割和开放环境识别；
- DETR、Mamba、Transformer-CNN 混合模型；
- 监督多任务学习和病害严重度估计；
- 背景偏差、域泛化、跨作物迁移和未知类识别。

每篇候选论文至少记录：

- 任务类型；
- 数据采集背景；
- 数据规模和标注类型；
- 模型骨干与真正的改进点；
- 对照模型；
- 是否有独立跨场景测试；
- 是否公开代码和数据；
- 能否在 RTX 4060 Ti 16 GB 上复现；
- 能迁移到本项目的具体部分；
- 与本地已有方案是否重复。

### 7.2 方法候选输出要求

新 Agent 不要只列模型名称。至少给出三套相互独立、可比较的方案：

1. 监督分类或分类 + 局部病斑分支；
2. 检测路线，对比 YOLO、Faster R-CNN 和 RT-DETR；
3. 分割/多任务路线，输出病斑和严重度。

每套方案必须说明：

- 为什么适合这 190 张自采图；
- 需要什么标签；
- 标注成本；
- 用哪些公开跨作物数据预训练；
- 主创新是什么；
- 基线和消融怎么设计；
- 最大风险与兜底方案。

### 7.3 建议的先导实验

在正式锁题前，建议从自采图中选择经专家确认的 100—150 张，建立小规模先导集，同时跑：

- ConvNeXt-Tiny/Swin-T 分类；
- YOLOv8n、Faster R-CNN、RT-DETR 检测；
- SegFormer-B1/B2 或 Mask R-CNN 分割。

比较的不只是 Accuracy/mAP/mIoU，还应包括：

- 标注时间；
- 小病斑召回；
- 背景误检；
- 相似症状混淆；
- 跨拍摄者测试；
- 推理速度和显存；
- 人工可解释性。

最终根据错误类型选择研究路线，而不是先决定网络再寻找问题。

## 8. 接手时不得重复犯的错误

1. 不要将 TFDS、Kaggle 镜像和 Mendeley Citrus 当成三个独立数据集。
2. 不要把 CitrusUAT 描述为复杂田间背景。
3. 不要直接把黄化叶片标成黄龙病。
4. 不要随机拆分同一叶/同一果的连续照片。
5. 不要让水印、记号笔和拍摄设备成为类别线索。
6. 不要把真实运行结果等同于严格合格的论文实验协议。
7. 不要仅凭单次 DANN 结果宣称方法稳定有效。
8. 不要把 SimCLR 70.59% 写成优于 ImageNet 预训练。
9. 不要为了避开 YOLO 而机械换成 DETR；任务、数据和误差分析才是依据。
10. 不要给每个模块包装“创新”名称；创新必须对应具体困难并有消融验证。
